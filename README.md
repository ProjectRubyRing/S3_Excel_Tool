# s3log2xlsx.sh

S3 の指定プレフィックス配下にあるすべてのログファイルから、指定期間内に出力されたログ行を抽出し、
**S3 のファイルごとにシートを分けた Excel ファイル（.xlsx）** を作成するシェルスクリプトです。

- 実行前に `aws login --remote` による認証済みかを確認し、未認証なら警告して終了します。
- 現在の権限で S3 を参照できない場合は、スイッチバックを促して終了するか、
  別チームのスイッチバック用シェルを `source` して自動でスイッチバックします（オプションで切り替え）。
- 指定した文言を Excel 上で色分けして強調表示します。フォントはすべて Meiryo UI です。

## 動作環境

| 項目 | 内容 |
| --- | --- |
| OS | RHEL 9 系（RHEL 9.8 で確認） |
| シェル | bash 5.1（OS 標準） |
| Python | python3 3.9（OS 標準）。**標準ライブラリのみ使用し、追加インストールは不要** |
| AWS CLI | v2.32.0 以降（`aws login` に対応したバージョン） |

Excel の作成も Python の標準ライブラリだけで行います（openpyxl などは使いません）。

## 導入

```bash
chmod +x s3log2xlsx.sh
# スイッチバック用シェルの場所を既定値として設定しておく場合（任意）
export S3LOG2XLSX_SWITCHBACK_SCRIPT=/opt/team/bin/switchback.sh
```

## 使い方

```bash
# 事前に認証しておく
aws login --remote

# 9:00〜10:00 のログを抽出し、ERROR / WARN / Timeout を強調表示する
./s3log2xlsx.sh -s s3://app-logs/web/ -f "2026-10-04 09:00" -t "2026-10-04 10:00" \
    -o web_0900-1000.xlsx -k ERROR -k WARN -k Timeout

# 直近 3 時間分。権限が足りなければ自動でスイッチバックする
./s3log2xlsx.sh -s s3://app-logs/batch/ -f -3h -o batch.xlsx -k Exception \
    --switchback auto --switchback-script /opt/team/bin/switchback.sh
```

オプションの一覧は `./s3log2xlsx.sh --help` で確認できます。

## 実行前のチェック

### 1. aws login の認証

`login_session` が設定されたプロファイル（`AWS_PROFILE` → `default` の順に探索。`source_profile` もたどります。
`--login-profile` で明示も可能）について、`aws sts get-caller-identity` で認証が有効かを確認します。
未認証・有効期限切れの場合は、実行すべきコマンド（`aws login --remote`）を表示して終了します（終了コード 10）。

この確認では環境変数の認証情報（スイッチロール中の `AWS_ACCESS_KEY_ID` など）を外して実行するため、
スイッチ中でも aws login 自体の状態を正しく判定できます。

### 2. S3 を参照する権限とスイッチバック

現在の認証情報で、対象プレフィックスの一覧取得（`s3:ListBucket`）と先頭オブジェクトの読み取り
（`s3:GetObject`）を実際に試します。参照できない場合の動作は `--switchback` で切り替えます。

| モード | 動作 |
| --- | --- |
| `warn`（既定） | 理由・現在の ID・実行すべき `source <スイッチバック用シェル>` を表示して終了（終了コード 11） |
| `auto` | スイッチバック用シェルを `source` で呼び出し、権限を再確認して処理を続行 |

- スイッチバック用シェルの場所は `--switchback-script` または環境変数 `S3LOG2XLSX_SWITCHBACK_SCRIPT` で指定します。
  引数が必要な場合は `--switchback-arg`（複数指定可）で渡せます。
- 本ツールは CodeCommit を操作しないため、スイッチバックして問題ありません。
- `auto` のスイッチバックは**本ツールの処理中だけ**有効です。実行元のシェルの状態（CodeCommit 用の権限など）は変わりません。
- 呼び出し先のシェルが `set -e` / `set -u` / トラップ / `IFS` / カレントディレクトリを変更しても、本ツールには影響しません。
  `export` せずに設定された `AWS_` で始まる変数も aws コマンドに引き継ぎます。
- スイッチバック後も参照できない場合は終了コード 12、スイッチバック用シェルの中で `exit` された場合はその旨を表示して終了します。

## 期間とタイムゾーン

- 日時は `"2026-10-04 09:00"`、`"2026/10/04 09:00:30"`、`"2026-10-04T09:00:00+09:00"`、`"2026-10-04"`、
  `"09:00"`（本日）、`-2h` / `-30m` / `-1d`、`now` / `today` / `yesterday` で指定できます。
- **終了日時は指定した精度の終わりまでを含みます。** `-t "2026-10-04 10:00"` は 10:00:59.999 まで、
  `-t 2026-10-04` はその日の 23:59:59.999 までです。
- `--tz` は期間指定と Excel 表示のタイムゾーン（既定: OS の設定）です。
- ログ内の日時にタイムゾーン表記がない場合は `--log-tz`（既定: `--tz` と同じ）として解釈します。
  CloudFront のログのように **表記なしで UTC のログ** は `--log-tz UTC` を指定してください。
  ALB のログなど `Z` や `+09:00` が付いた日時は自動で変換されます。

### ログ日時の自動判定

ISO 8601、`YYYY/MM/DD hh:mm:ss`、Apache / Nginx、syslog（年なし）、Tomcat、Java、`YYYY年MM月DD日 hh時mm分ss秒`、
JSON（`time` / `timestamp` / `ts` など。エポック秒・ミリ秒も可）を自動で判定します。
日時を含まない行（スタックトレースなど）は直前のログ行と同じ日時として扱うため、複数行のログもまとめて抽出されます。

判定できない形式は `--ts-regex` と `--ts-format` で指定します。

```bash
# VPC フローログ（11 番目の項目がエポック秒）
--ts-regex '^(?:\S+ ){10}(\d{10}) ' --ts-format epoch
# [04.10.2026 09:15:00] 形式
--ts-regex '^\[(?P<ts>[^\]]+)\]' --ts-format '%d.%m.%Y %H:%M:%S'
```

## 出力される Excel

**サマリーシート**（先頭）
- 対象 S3・抽出期間・強調文言・処理結果・実行 ID・作成日時
- ファイルごとの一覧（シートへのリンク、最終更新日時、サイズ、抽出行数、総行数、強調文言ごとの該当行数、状態）と合計

**ログのシート**（S3 のファイルごとに 1 シート）
- 見出し: ファイル名、S3 の場所、最終更新日時、サイズ、文字コード・圧縮形式、日時の形式、抽出行数、期間、
  実際のログの時刻の範囲、強調文言ごとの件数
- 表: 行番号（元ファイルの行番号）／日時（Excel の日付として表示タイムゾーンに変換）／ログ
- 強調文言は太字の色文字で表示し、その行の背景も同系色にします（文言は指定した順に赤・黄・青・緑・紫…）。
  強調文言を含むシートは、シート見出し（タブ）にも色が付きます。
- 1 件のログ（スタックトレースなどの継続行を含む）ごとに縞模様を付け、継続行の日時は薄い色で表示します。
- 見出しと行番号・日時の列は固定表示、オートフィルター付き。列幅は内容に合わせて調整します。
- ログ列は既定では折り返さずに表示します。`--wrap` を指定すると折り返して表示します。

## 対象ファイルの扱い

- gzip / bzip2 / xz で圧縮されたファイルは自動で展開します（拡張子ではなく内容で判定）。zip には対応していません。
- 文字コードは UTF-8 / EUC-JP / Shift_JIS（CP932）を自動判定します（`--encoding` で固定も可能）。
- 最終更新日時が「開始日時 − 60 分」より前のファイルは、期間内のログを含まないため読み込みません（`--mtime-margin` で変更）。
- テキストでないファイル・空のファイル・日時を検出できないファイルは出力せず、サマリーに状態を表示します
  （日時のないファイルは `--untimed all` で全行を出力できます）。
- 安全のため、読み込むファイルが 500 件を超える場合は処理しません（`--max-files` で変更）。

## 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 正常終了 |
| 1 | エラー（バケットがない、接続できないなど） |
| 2 | 引数の誤り |
| 3 | 条件に合うファイルがない（Excel は作成しません） |
| 4 | Excel は作成したが、一部のファイルを読み込めなかった（サマリーの「状態」を参照） |
| 10 | aws login が未認証、または有効期限切れ |
| 11 | 権限不足のためスイッチバックが必要（`--switchback warn`） |
| 12 | スイッチバック後も S3 を参照できない |

## 必要な権限

- `s3:ListBucket`（対象バケット）、`s3:GetObject`（対象オブジェクト）
- SSE-KMS で暗号化されている場合は `kms:Decrypt`
- `aws login` を使うための `SignInLocalDevelopmentAccess`（マネージドポリシー）相当の権限

## 制限事項

- Excel の 1 シートの上限（1,048,576 行）を超える場合は、「ファイル名 #2」のように続きのシートに分けて出力します。
- 1 セルの上限（32,767 文字）を超える行は切り詰め、末尾に省略した文字数を表示します。
- 色付けの制御文字（ANSI エスケープシーケンス）と制御文字は取り除き、タブは空白に置き換えて表示します。
- `--wrap` 指定時、極端に長い行は Excel の行の高さの上限（409 ポイント）までしか表示されません。
